# Supabase 云端配置步骤（手把手）

> 全程免费。不会产生任何费用。
> 整个过程大约需要 10 分钟。

---

## 第 1 步：注册并创建项目

1. 打开 <https://supabase.com>，点右上角 **Sign Up**，用邮箱注册（可用 GitHub 账号一键登录）。
2. 登录后点 **New project**。
3. 填写：
   - **Organization**：用默认的即可
   - **Name**：随便起，比如 `my-wardrobe`
   - **Database Password**：点 **Generate a strong password**，**复制保存到密码管理器**。
     > 这个密码是数据库管理员密码，它**只会在控制台里用**，
     > 我们的应用**永远不需要它**，也不要填进应用里。
   - **Region**：选离你近的（如 Northeast Asia / Singapore），国内访问通常更流畅
   - **Plan**：保持 **Free**
4. 点 **Create new project**，等 1～2 分钟，页面提示数据库创建完成。

---

## 第 2 步：建表 + 开权限（约 2 分钟）

1. 左侧菜单点 **SQL Editor** → 点 **New query**。
2. 打开本项目里的 `supabase/schema.sql` 文件，**全选复制**，粘贴到 SQL 编辑器里。
3. 点右下角 **Run**（或按 Ctrl+Enter）。
4. 看到 `Success. No rows returned` 就说明执行成功。

这一步会做好四件事：
- 建 `garments`（衣服）、`wash_logs`（洗衣记录）、`custom_assets`（自定义图片）三张表，
  每张表都带 `user_id`，用来标记这条数据属于哪个用户；
- 开启 **RLS 行级安全**并写好策略：**每个用户只能读写自己 user_id 的行**，
  别人（包括没登录的人）一条都看不到；
- 建一个 `photos` 私有存储桶，同样按用户目录隔离，别人也拿不到你的照片；
- 建 `next_garment_sequence()` 函数：在数据库端分配编号，
  保证手机和电脑同时添加也不会撞号。

> **RLS 是数据隔离的真正保障**，不是前端过滤。
> 即使有人绕过应用直接调数据库接口，也会被数据库挡住。

---

## 第 3 步：拿到项目地址和 anon 密钥

1. 左侧菜单点 **Project Settings**（齿轮图标）→ **API**。
2. 找到两个值：
   - **Project URL**：形如 `https://abcdefghijkl.supabase.co`
   - 密钥区域里有两把钥匙：
     - **anon** 或 **publishable**（新项目显示的是 `sb_publishable_...`）← **用这个**
     - **service_role** ← ⚠️ **绝对不要复制这个**
3. 把 **Project URL** 和 **anon/publishable key** 复制下来。

> **为什么 anon key 可以公开？**
> 因为它被 RLS 策略限制住了：拿着它只能读到「已登录用户自己的数据」。
> 这正是它该有的样子 —— 前端本来就需要它来跟数据库通信。
>
> **为什么 service_role 绝对不行？**
> 它是管理员权限，能读写所有人的数据（包括别人的照片）。
> 它一旦出现在公开的前端代码里，任何人打开开发者工具就能拿走，
> 相当于把整个数据库的钥匙挂在门口。

---

## 第 4 步：关闭邮箱验证（可选，但强烈建议）

`Authentication` → `Providers` → **Email** → 把 **Confirm email** 关掉。

这样注册完能直接登录，不用先去邮箱点确认链接。
（如果你想保留邮箱验证，就保持打开，注册后去邮箱点一下确认链接。）

---

## 第 5 步：填进应用

有两种方式，二选一：

**方式 A：在应用里填（推荐，手机上也能改）**

打开应用 → **设置** → **云端同步** →
- 「项目地址」填 Project URL
- 「anon public 密钥」填 anon key
- 点 **保存云端配置**
- 填邮箱密码 → 点 **注册新账号** → 自动登录

**方式 B：写进 .env 文件（部署到 Vercel 时用这个）**

在项目根目录复制一份 `.env.example` 改名为 `.env`，填入：

```
VITE_SUPABASE_URL=https://abcdefghijkl.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_xxxxx
```

`.env` 已在 `.gitignore` 里，**不会被提交到 GitHub**。

---

## 第 6 步：迁移你现有的衣服数据

登录之后，在 **设置 → 云端同步** 里会看到：

> 这台设备上还存着 N 件只保存在本机的衣服。要一起上传到云端吗？

点 **上传本机数据到云端** 即可。

这个操作是**安全**的：
- 上传前会自动在本机存一份迁移备份，即使上传失败也能恢复；
- 记录了「已迁移到哪个账号」，同一个账号不会重复导入；
- **本机数据不会被删除**，导出备份功能随时可用；
- 照片会一起上传。

## 出问题怎么办

**注册时提示「Database error」**
→ 多半是邮箱验证没关或者密码太短。密码至少 6 位。

**登录提示「Invalid login credentials」**
→ 邮箱或密码不对。注意密码区分大小写。

**点「立即同步」后列表是空的，但本机明明有衣服**
→ 需要先做第 6 步的迁移。

**照片显示不出来**
→ 检查第 2 步的 SQL 是否执行成功（照片桶和权限都在那一步创建）。

**「忘记密码」收不到邮件**
→ 检查垃圾邮件箱；Supabase 免费版的邮件送达率一般，可以改用方式 B 直接换密码。
